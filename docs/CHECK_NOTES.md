## Fixes

1.  `R/caliber-package.R`: roxygen2 8 rejects a two-line `@importFrom`,
    so it is now split into two lines. The first check gave 2 NOTEs, now
    fixed:
    - [`scenario_truth()`](https://paoloeusebi.github.io/caliber/reference/scenario_truth.md)
      called `gauss.quad.prob()` without importing it. That would have
      been a runtime error. Added `@importFrom statmod gauss.quad.prob`.
    - `hcl.colors`, `head` and `tail` were not imported. Added
      `@importFrom grDevices hcl.colors` and
      `@importFrom utils head tail`, and put `grDevices` in Imports.
2.  NAMESPACE is now generated by roxygen, with the same 43 exports as
    the hand-written file (backup at
    `%TEMP%\monocal_NAMESPACE_handwritten.bak`). roxygen replaced
    `RoxygenNote` with `Config/roxygen2/version: 8.0.0` and, after the
    rename, swapped `man/monocal-package.Rd` for
    `man/caliber-package.Rd`.
3.  `R/intervals.R`: on a PSOCK cluster (the scripts’ default),
    [`ms_bootstrap()`](https://paoloeusebi.github.io/caliber/reference/ms_bootstrap.md)
    failed every resample and then crashed
    (`attempt to set an attribute on NULL`). There were two causes:
    - `summary_fun` in the scripts is a global closure that uses script
      globals (`items`, `eta_report`, `curve_grid`), and the workers did
      not have them. The original ms scripts `clusterExport`ed these
      objects. Now `global_refs()` collects the global objects that
      `summary_fun` refers to (also through global functions it calls),
      and `run_jobs(..., export =)` exports them.
    - `seed` and the other arguments were unevaluated promises pointing
      at the global env. They are now
      [`force()`](https://rdrr.io/r/base/force.html)d. A failed resample
      now returns its error message, and if every resample fails the
      function stops with the first error. The method is unchanged.

    (mu_m3), 5.8e-6 (df), 3.7e-6 (sigma0), 3.5e-6 (-2logL); relative

    `ms/R/ms_functions.R` gives **exactly** the package’s fit (a, d, df,

    the concurrent GRM updates), not a porting difference. It is far
    below the reported precision.
